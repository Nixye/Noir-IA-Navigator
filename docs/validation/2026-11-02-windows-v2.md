## Comportamentos cobertos

Os testes verificam perfil/backup, privacidade da restauração, favoritos, independência de abas/histórico/consulta entre espaços, movimentação, navegação transacional e formulários GET. O JavaScript tem testes de parser, escopos, closures, ordem de avaliação, DOM, rollback, inputs como dados, eventos, timers e orçamentos. Esgotamento em callback desativa scripts/tarefas restantes e impede polling contínuo de tarefas bloqueadas.

Subprocessos comprovam estado entre cliques/reflow, valores editados observados pela VM, timer com prazo positivo e sessão remota no AppContainer. Provas Windows verificam token, ausência de capabilities e recusa de leitura/escrita externa, rede e processo filho. O worker comum recusa origem remota.

## Inspeção visual

Framebuffers reais egui/wgpu inspecionados em 1280 × 860: inicial com favoritos/espaços e inicial com painel de IA. A interface exibiu “IA local pronta” após a carga do modelo. A grade de favoritos se adapta ao painel. Captura externa do desktop não isolou corretamente a janela; as referências usam o framebuffer do aplicativo.

A árvore de acessibilidade expôs campos/botões de `javascript-session.html`. Isso não equivale a ensaio completo de teclado ou acessibilidade. A janela permaneceu aberta para uso; testes automatizados verificam as transações separadamente.

## Limites materiais

A homepage Google foi carregada por HTTP e renderizada pelo motor próprio. Resultados de buscas reais podem exigir JavaScript/redirecionamentos não implementados. Google é a pesquisa padrão, sem alegação de busca plenamente funcional.

JavaScript é um subconjunto original: módulos, Promises, async/await e muitas Web APIs faltam. TypeScript precisa ser compilado pelo site para JavaScript, sujeito aos mesmos limites. GET básico existe; POST/submissão completa não. Linux remoto permanece desativado até verificar sandbox equivalente. Não foram executados Test262/WPT completos, auditoria independente, validação gráfica Linux ou testes prolongados.
